## 3. How it works

**`redis.js`** follows the style of `db/index.js`: CommonJS, `require('dotenv').config()` straight after the library require, and a single `module.exports = redis;`.

- **Fail fast on missing config.** If `REDIS_URL` is unset, empty or only whitespace, the module throws `REDIS_URL is not set; add it to backend/.env` when it loads. Without this check, ioredis would quietly connect to `localhost:6379`, which hides a misconfiguration on any machine that happens to run a local Redis.
- **`retryStrategy: times => Math.min(times * 200, 5000)`.** ioredis keeps reconnecting forever, but backs off to at most one attempt every 5 s, so an outage doesn't spin the CPU.
- **`maxRetriesPerRequest: 1`.** While Redis is down, commands such as the startup PING fail within about 0.6 s instead of waiting indefinitely in the offline queue.
- **`error` listener with an `inOutage` flag.** It logs only the first error of an outage, and logs `Redis connection restored` on the next `ready`. Without a listener, ioredis prints a full stack trace on every reconnect attempt. (The brief assumed a missing listener would crash the process. The reviewer showed it doesn't in ioredis 6, and the code comment was corrected.)
- **`describeError(err)`.** On Windows, `localhost` resolves to both `::1` and `127.0.0.1`, so a refused connect arrives as an `AggregateError` whose `message` is empty. The helper joins `err.errors[]`, then falls back to `message`, then `code`, then `String(err)`.

**Startup ping in `index.js`.** It mirrors the existing `SELECT 1` block inside the `listen` callback: `await redis.ping()` logs `Redis connection succeeded`, and a failure logs `Redis connection failed: <msg>`. There is deliberately no `process.exit`. A Redis outage must not take down chat, and whether rate limiting should fail open or closed is still the user's call.

**One client only.** Every future consumer (the A3 rate-limit store and others) must `require('./redis')` instead of creating its own connection.

## 5. Bugs found and fixed

1. **Empty Redis error message during an outage** (found by T2 on the first run).
   - **Symptom:** the outage was logged as `Redis error: ` with nothing after it.
   - **Root cause:** on Windows, `localhost` resolves to both `::1` and `127.0.0.1`, and Node tries both. The two refusals are wrapped in an `AggregateError` whose top-level `message` is `""`, and the handler logged `err.message`.
   - **Fix:** a `describeError` helper in `redis.js` that prefers the joined `err.errors[]` messages. The `localhost` URL was kept.
2. **Misleading comment** (found by the reviewer).
   - **Problem:** the comment claimed that without an `error` listener ioredis would crash the process.
   - **Actual behaviour:** ioredis 6 uses `silentEmit` (`node_modules/ioredis/built/Redis.js:580-584`), which prints a stack trace instead of crashing.
   - **Fix:** the comment now states the real reason (log flood). The long `describeError` line was also wrapped. Behaviour is unchanged.
